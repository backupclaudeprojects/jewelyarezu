# 06 — به‌روزرسانی امن: «هیچ تغییری ریست نشود»

> خواستهٔ تکرارشونده و مؤکد صاحب سایت: «من کلی تغییرات روی سایت دادم، نمی‌خواهم هیچ‌کدام با نصب
> نسخهٔ جدید ریست شوند» — «هیچ تنظیماتی که تا الان انجام دادم تغییر نکند، فقط ویژگی‌های جدید اضافه شود».

## چه چیزهایی مال صاحب سایت است (دست نزن)
- `_elementor_data` همهٔ صفحه‌ها و قالب‌ها (هدر، فوتر، هیرو، قاصدک‌هایی که دستی اضافه کرده...)
- کیت المنتور (رنگ/فونت سراسری)، option های افزونه، متای آیتم‌ها، منوها، رسانه.

## روال ارتقا (plugins_loaded)
```php
function pfx_maybe_upgrade() {
  $from = get_option( 'brand_version' );
  if ( $from === PFX_VERSION ) return;
  pfx_ensure_types();          // افزودن term های لازم اگر نبودند (نه تغییر نام موجودها)
  pfx_set_site_icon_if_empty();
  update_option( 'brand_version', PFX_VERSION );
  // هیچ بازنویسی چیدمانی اینجا نیست.
}
```
تابع‌های مهاجرت چیدمان (مثل `pfx_upgrade_120`) اگر لازم شدند: فقط از دکمهٔ صریح «اعمال پیشنهادهای
نسخهٔ X روی سایت من»، با پشتیبان هر صفحه و بازگردانی، و فهرست دقیق تغییرات قبل از اعمال.

## قانون پیش‌فرض‌ها (مهم‌ترین تلهٔ المنتور)
المنتور هنگام ذخیره، تنظیمی را که برابر پیش‌فرض است **ذخیره نمی‌کند**. پس:
- ❌ تغییر `default` یک کنترل موجود ⇒ همهٔ ویجت‌هایی که آن را دست نزده بودند رفتارشان عوض می‌شود.
- ❌ تغییر CSS پیش‌فرض یک کلاس/متغیر موجود ⇒ همان اثر.
- ❌ حذف/تغییر نام شناسهٔ کنترل ⇒ مقدار ذخیره‌شدهٔ کاربر یتیم می‌شود.
- ✅ رفتار تازه = کنترل تازه، با پیش‌فرضی که **دقیقاً رفتار قدیم** را تولید کند (مثلاً
  `f_m_shape` پیش‌فرض `wide` = همان قاب افقی قبلی).
- ✅ اگر شناسه مجبوراً عوض شد (تداخل با پرو): در render بخوان `$s['pr_pin'] ?? $s['sticky'] ?? ''`.
- ✅ ریپیتر: فیلد تازه در ردیف‌های قدیمی وجود ندارد ⇒ `empty($row['for'])` را برابر «همه» بگیر.
- ✅ داده‌های تازهٔ پیش‌فرض (مثل ناحیه‌های متحرک برای عکس موبایل) فقط به‌عنوان **فال‌بک زمان رندر**
  وقتی کاربر چیزی تعریف نکرده؛ نه نوشتن در دیتابیس.

## option ها
- همیشه `wp_parse_args( get_option(...), defaults )` ⇒ کلید تازه خودکار. هرگز `update_option` با
  پیش‌فرض‌ها روی option موجود.
- فهرست‌های تازه (مثل شبکه‌های اجتماعی) تا اولین ذخیره از فیلدهای قدیمی ساخته شوند (فال‌بک) و
  ذخیرهٔ جدید فیلدهای قدیمی را هم همگام کند (سازگاری عقب‌رو).

## CSS و JS
- کلاس‌ها/متغیرهای موجود را تغییر معنا نده؛ کلاس تازه اضافه کن.
- اصلاح باگ ظاهری که «درست»ترش کند مجاز است، ولی در گزارش تحویل صریحاً بگو چه چیزی دیده‌شدنی عوض شد.

## اثبات قبل از تحویل
```php
// قبل از نصب نسخهٔ جدید روی سایت تست (کپی سایت با ویرایش‌های دستی شبیه‌سازی‌شده)
foreach ( $layouts as $id ) $before[ $id ] = md5( get_post_meta( $id, '_elementor_data', true ) );
// نصب/فعال‌سازی نسخهٔ جدید، اجرای ارتقا، بازدید صفحه‌ها
// بعد: تعداد چیدمان‌های تغییرکرده باید 0 باشد
```
و یک ویرایش دستی عمدی (مثلاً عنصر شناور اضافه) قبل از ارتقا بساز و بعد از ارتقا وجودش را بررسی کن.
در پیام تحویل بنویس: «X از X چیدمان بدون تغییر ماند».

## بعد از نصب (به کاربر بگو)
المنتور ← ابزارها ← «بازسازی CSS و داده» + پاک کردن کش افزونهٔ کش/CDN + رفرش سخت مرورگر.
