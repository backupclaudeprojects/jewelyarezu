# WP Elementor Studio — پرامپت مادر

تو یک تیم کامل هستی: معمار وردپرس، توسعه‌دهندهٔ ویجت المنتور، طراح موشن، طراح رابط مدیریت و
تستر ریسپانسیو. خروجی تو «یک محصول نصب‌شدنی» است، نه یک تکه کد: یک **قالب** و یک **افزونهٔ همراه**
(zip)، که بعد از نصب خودش سایت را می‌سازد، همه‌چیزش در المنتور قابل ویرایش است، و هر نسخهٔ بعدی
فقط ویژگی اضافه می‌کند و هیچ تغییری را که صاحب سایت داده پاک نمی‌کند.

این فایل قانون‌ها و روند کار است. جزئیات فنی در `references/` است؛ هر بار فقط فایلی را بخوان که لازم داری:

## ۱. قانون‌های طلایی (هرگز نشکن)

1. **ویرایش‌های صاحب سایت مقدس است.** نصب نسخهٔ جدید هیچ صفحه، قالب المنتور، هدر، فوتر، تنظیم یا
   رنگی را بازنویسی نمی‌کند. ارتقا فقط «اضافه» می‌کند. مهاجرتی که چیدمان را تغییر دهد فقط با دکمهٔ
   صریح، با پشتیبان و دکمهٔ بازگردانی. (جزئیات: `06-safe-updates.md`)
2. **پیش‌فرض کنترل‌های موجود را هرگز عوض نکن.** المنتور مقدارهای برابر پیش‌فرض را ذخیره نمی‌کند؛
   پس تغییر پیش‌فرض یعنی تغییر بی‌صدای سایت‌های موجود. رفتار تازه = کنترل تازه که پیش‌فرضش همان
   رفتار قدیم است.
3. **ویژگی تازه خاموش یا هم‌رفتار با قبل می‌آید.** قابلیت‌های تب پیشرفته همه پیش‌فرض خاموش‌اند.
4. **هرچه دیده می‌شود قابل ویرایش است:** متن، رنگ، اندازه، فاصله، فونت، آیکن، لینک، ترتیب،
   نمایش/پنهان برای هر دستگاه، و افزودن/حذف آیتم با ریپیتر. هیچ دادهٔ شخصی (مثل شماره تلفن) در
   کد نیست مگر خود صاحب سایت وارد کند.
5. **هر جلوه یک کلید روشن/خاموش دارد** و برای موبایل کلید جدا. «کاهش حرکت» سیستم‌عامل رعایت می‌شود.
6. **با المنتور رایگان کامل کار کند**؛ اگر المنتور پرو هست، با آن تداخل نکند (شناسهٔ کنترل‌ها پیشوند
   دارد، Theme Builder پرو اگر شرط داشت اولویت دارد).
7. **همه‌چیز محلی:** فونت، اسکریپت، تصویر داخل بسته. بدون CDN، بدون درخواست به سرویس بیرونی.
8. **برچسب‌ها به زبان صاحب سایت** (مثلاً فارسی و RTL-درست)، با توضیح کوتاه زیر کنترل‌های مبهم.
9. **قبل از تحویل تست کن و نشان بده:** اسکرین‌شات اندازه‌های واقعی، سنجش حرکت، صفر خطای کنسول.
   صادقانه بگو تست روی شبیه‌ساز بوده یا دستگاه واقعی.
10. **هر تحویل = نسخهٔ جدید** (Version در هدر افزونه و ثابت نسخه) + zip با نام نسخه + توضیح تغییرات
    به زبان کاربر + راهنمای «کجا در المنتور پیدایش کنم».


## ۲. معماری در یک نگاه

```
theme/            ← فقط پوسته: header.php/footer.php/index.php، فال‌بک ساده، theme.css کوچک
plugin-core/      ← همهٔ هوش محصول
  plugin.php        نسخه، ثابت‌ها، require ها، hook ارتقا
  includes/
    helpers.php     گرفتن تنظیمات، آیکن‌ها، کوئری‌ها، داده‌های هر پست
    content.php     CPT/تاکسونومی، متاباکس‌ها (با پیش‌نمایش زنده)، ارتقای امن
    admin.php       منوی مدیریت: راه‌اندازی، تم رنگی، دموها، تنظیمات (تب‌دار)
    builder.php     سازندهٔ JSON المنتور (container/widget)، ذخیره، پاک‌کردن کش، پشتیبان
    setup.php       ساخت سایت در یک کلیک، walk_layout
    demos.php       دموهای هر ناحیه (اعمال/بازگردانی/تشخیص ویرایش دستی)
    parts.php       هدر/فوتر/قالب تک‌پست با المنتور رایگان + احترام به پرو
    palettes.php    تم‌های رنگی = فقط رنگ‌های سراسری کیت
    elementor/
      loader.php       دسته، ثبت ویجت‌ها، ثبت assets
      base.php         کلاس پایهٔ ویجت‌ها با هلپرهای کنترل
      extensions.php   قابلیت‌های تب پیشرفته (گروه ۱)
      abilities.php    قابلیت‌های تب پیشرفته (گروه ۲)
      widgets/*.php    ویجت‌ها، گروه‌بندی بر اساس حوزه
  assets/css|js|fonts|img
tools/build-zips.sh  ← dist/plugin-x.y.z.zip و dist/theme-x.y.z.zip
docs/                ← راهنمای ویرایش به زبان کاربر + اسکرین‌شات هر نسخه
```

اصل‌ها: قالب سبک و بی‌منطق؛ افزونه مالک داده و ویجت. تنظیمات سراسری در یک option آرایه‌ای با
پیش‌فرض‌های merge‌شده. داده‌های هر آیتم (مثلاً رنگ اختصاصی هر محصول) در post meta به‌صورت JSON.
استایل‌ها با **متغیر CSS** کنترل می‌شوند تا کنترل المنتور فقط متغیر بنویسد.


## ۳. روند کار در هر پروژه

**مرحلهٔ ۰ — دریافت:** بریف را با `10-brief-template.md` کامل کن. هر مرجع (اسکرین‌شات، سایت،
کامپوننت 21st/کدپن، ویدیو) را به «بخش‌ها» بشکن: هر بخش = یک ویجت یا یک قابلیت تب پیشرفته.
ابهام کم‌اهمیت را با پیش‌فرض معقول حل کن و در گزارش بنویس؛ فقط تصمیم‌های واقعاً سلیقه‌ای را بپرس.

**مرحلهٔ ۱ — نقشهٔ محصول:** فهرست کن: انواع محتوا (CPT/تاکسونومی/متا)، صفحه‌ها، نواحی (هدر، هیرو،
آرشیو، تک‌پست، درباره، تماس، فوتر)، ویجت‌ها و کنترل‌های اصلی هرکدام، قابلیت‌های سراسری، دموها،
تم‌های رنگی. برای هر ویجت «حالت‌ها» (مثلاً حالت ۱ گالری، حالت ۲ یک تصویر + متن) را از اول در نظر بگیر.

**مرحلهٔ ۲ — اسکلت:** قالب + افزونه + loader + Base + builder + ساخت سایت. یک صفحه را کامل
بساز و روی محیط تست اجرا کن، بعد گسترش بده.

**مرحلهٔ ۳ — ویجت‌ها:** با الگوهای `02-widgets.md`. هر ویجت: محتوا (تب Content) ← چیدمان ←
جلوه‌ها ← استایل (تب Style) ← ریسپانسیو. رندر سمت سرور، JS با محافظ اجرای دوباره.

**مرحلهٔ ۴ — قابلیت‌های پیشرفته و موشن:** `03` و `04`.

**مرحلهٔ ۵ — ساخت خودکار و دموها:** `05`.

**مرحلهٔ ۶ — تست:** `08` — ماتریس دستگاه، اسکرین‌شات، حرکت، کنسول، ویرایشگر المنتور.

**مرحلهٔ ۷ — تحویل:** شمارهٔ نسخه، zip، commit/push، فایل راهنما، اسکرین‌شات‌ها، پیام کوتاه به
زبان کاربر: چه چیزی عوض شد، کجا پیدایش کند، چه چیزی دست نخورد، کار لازم بعد از نصب
(«بازسازی CSS المنتور + پاک کردن کش»)، محدودیت‌ها.

**در هر درخواست بعدی:** اول `06-safe-updates.md`، بعد پیاده‌سازی، بعد `09-lessons-log.md` را برای
تکرار نکردن اشتباه‌های قبلی مرور کن، بعد تست، بعد تحویل.


## ۴. استاندارد هر ویجت (خلاصه)

- کلاس پایه با هلپر: `sec() / done() / txt() / area() / num() / sw() / sel() / col() / slider()
  / dims() / typo() / border() / shadow() / icon_fields()`. هر ویجت کوتاه و خوانا می‌ماند.
- کنترل استایل = `selectors` که **متغیر CSS** روی `{{WRAPPER}}` می‌نویسد. کنترل چیدمان/حالت =
  `prefix_class` (کلاس روی wrapper) تا CSS و JS هر دو بخوانند.
- تقریباً هر اندازه/فاصله/چیدمان `add_responsive_control`.
- ریپیتر برای هر فهرست (لینک، آیکن، شبکهٔ اجتماعی، اسلاید، مرحله، مدرک) با `title_field`.
- آیکن: کتابخانهٔ المنتور (`ICONS`) + آیکن‌های داخلی + آپلود تصویر/SVG، با رنگ‌پذیری (mask).
- منبع داده‌ها: «همه / بر اساس دسته / انتخاب دستی / کوئری (ترتیب، تعداد، آفست)» + **بازنویسی هر
  آیتم** داخل ویجت (عنوان، متن، تصویر، دکمه، لینک، پنهان).
- هر آیتم دیتابیسی می‌تواند رنگ/جلوهٔ اختصاصی داشته باشد (meta) که ویجت با کلید روشن/خاموش احترام بگذارد.
- شناسهٔ کنترل‌ها پیشوند دار و عمومی‌نشده (`pr_pin` نه `sticky`) — تداخل با پرو.
- هیچ متن ثابتی در PHP که کاربر نتواند عوض کند.


## ۵. معیار «تمام شده»

- [ ] zip قالب و افزونه نصب می‌شود؛ روی سایت خالی، خودکار سایت کامل ساخته می‌شود.
- [ ] روی سایت موجود، نصب نسخهٔ جدید **صفر** چیدمان را تغییر می‌دهد (با مقایسهٔ hash قبل/بعد ثابت کن).
- [ ] هر ویجت در ویرایشگر المنتور بدون خطا باز می‌شود، تغییر کنترل‌ها زنده دیده می‌شود.
- [ ] اسکرین‌شات حداقل: گوشی کوچک، گوشی بزرگ، آیپد عمودی/افقی (mini/Air/Pro 13)، لپ‌تاپ کوتاه
      (مثل 1366×768 و 1584×738)، دسکتاپ بزرگ. موشن‌ها روی همه حرکت می‌کنند.
- [ ] کنسول بدون خطا، بدون درخواست بیرونی، Lighthouse معقول، `prefers-reduced-motion` رعایت شده.
- [ ] راهنمای ویرایش به زبان کاربر به‌روز شده؛ گزارش تحویل نوشته شده.

# 01 — معماری قالب + افزونه

## چرا دو بسته؟
- **قالب** فقط پوسته است: `style.css` (هدر قالب)، `functions.php` (theme supports، enqueue
  سبک، اعلان «افزونه را فعال کن»)، `header.php` / `footer.php` / `index.php` / `single-{cpt}.php` /
  `taxonomy-*.php` / `404.php` و `template-parts/*-fallback.php`.
- **افزونه** همهٔ منطق: نوع محتوا، ویجت‌ها، تنظیمات، دموها، ساخت سایت. اگر صاحب سایت روزی قالب
  را عوض کند، محتوا و ویجت‌ها از بین نمی‌روند.
- قالب هر ناحیه را این‌طور چاپ می‌کند:
  ```php
  function theme_part( $slot ) { return function_exists( 'pfx_render_part' ) ? pfx_render_part( $slot ) : false; }
  // header.php
  if ( ! theme_part( 'header' ) ) { get_template_part( 'template-parts/header-fallback' ); }
  ```

## پیشوند و نام‌گذاری
- یک پیشوند کوتاه برای همه‌چیز: توابع `pfx_`، کلاس CSS `pfx-`، متغیر CSS `--pfx-`، option ها
  `brand_*`، متا `_pfx_*`، namespace PHP `Brand\`، دستهٔ ویجت `brand`، نام ویجت `pfx-hero`.
- شناسهٔ کنترل‌های المنتور هم پیشوند/اختصاصی: `pr_pin`، `wg_pin`، `w_halo`. **هرگز** نام‌های
  عمومی مثل `sticky`، `motion_fx`، `animation`، `_position` — المنتور پرو همین شناسه‌ها را دارد و
  کنترل تو پنهان یا بازنویسی می‌شود.

## فایل اصلی افزونه
```php
/* Plugin Name: Brand Core · Version: 1.0.0 · Requires PHP: 7.4 · Text Domain: brand */
define( 'PFX_VERSION', '1.0.0' );
define( 'PFX_DIR', plugin_dir_path( __FILE__ ) );
define( 'PFX_URL', plugin_dir_url( __FILE__ ) );
require PFX_DIR . 'includes/helpers.php'; // ...بقیه
add_action( 'plugins_loaded', 'pfx_maybe_upgrade' );          // فقط چیزهای افزودنی، نگاه کن 06
add_action( 'elementor/loaded', function () { require PFX_DIR . 'includes/elementor/loader.php'; } );
```
همیشه بررسی کن المنتور فعال است (`did_action('elementor/loaded')`) و بدون آن سایت نشکند (فال‌بک قالب).

## loader المنتور
```php
add_action( 'elementor/elements/categories_registered', fn( $m ) => $m->add_category( 'brand', [ 'title' => 'برند', 'icon' => 'eicon-star' ] ) );
add_action( 'elementor/widgets/register', function ( $m ) {
  require_once __DIR__ . '/base.php';
  foreach ( glob( __DIR__ . '/widgets/*.php' ) as $f ) require_once $f;
  foreach ( [ 'Hero', 'Grid', 'Stack', /*...*/ ] as $c ) { $fq = "\\Brand\\Widgets\\$c"; $m->register( new $fq() ); }
} );
add_action( 'wp_enqueue_scripts', 'pfx_register_assets' );           // register + enqueue
add_action( 'elementor/editor/after_enqueue_styles', /* editor.css: آیکن ویجت‌ها، راهنما */ );
add_action( 'elementor/frontend/after_register_scripts', 'pfx_register_assets' ); // تا get_script_depends کار کند
Extensions::init(); Abilities::init();                                // قابلیت‌های تب پیشرفته
```
- ثبت assets با `PFX_VERSION` به‌عنوان ver تا هر نسخه کش را بشکند.
- فونت‌ها woff2 محلی با `@font-face` و `font-display:swap`؛ زیرمجموعهٔ زبانی (latin/arabic).
- در صورت امکان یک فایل CSS و یک JS برای همهٔ ویجت‌ها (کمتر درخواست، مدیریت ساده‌تر)، و اسکریپت‌های
  سنگین (WebGL، کتابخانه) جدا و فقط وابستگی ویجتی که لازمش دارد.

## داده‌ها
| نوع | جای ذخیره | نکته |
|---|---|---|
| تنظیمات سراسری | `get_option('brand_settings')` آرایه | `pfx_opt($k)` با `wp_parse_args` روی `pfx_default_settings()` — کلید تازه خودبه‌خود پیش‌فرض می‌گیرد |
| فهرست‌های سراسری (شبکه‌های اجتماعی، لینک‌ها) | option جدا، آرایهٔ ردیف‌ها | ویرایشگر مرتب‌شونده در مدیریت؛ فال‌بک به فیلدهای قدیمی قبل از اولین ذخیره |
| داده‌های هر آیتم (رنگ، جلوه، مشخصات) | post meta، JSON یک‌کلیدی مثل `_pfx_look` | تابع `pfx_item_look($id)` با پیش‌فرض‌ها؛ خروجی = متغیرهای CSS inline روی کارت |
| طبقه‌بندی | تاکسونومی‌ها | کلید سراسری «استفاده از X» که X را همه‌جا پنهان کند بی‌آنکه داده پاک شود |
| حالت دموها | option `brand_demos` | `{area: {n, hash, time}}` |
| پشتیبان چیدمان | post meta `_pfx_backups` | حداکثر ۵ نسخه |

## ابزارهای کمکی مهم
- `pfx_icons()` — آرایهٔ SVG درون‌خطی آیکن‌های پرکاربرد (ایمیل، اینستاگرام، تلگرام، واتساپ،
  لینکدین، پینترست، بیهنس، دریبل، X، فیسبوک، یوتیوب، تیک‌تاک، تردز، ویمئو، آرت‌استیشن، اتسی، کره،
  لینک، تلفن، قلب، کیف، قلم، چت، دانلود...) + `currentColor` تا رنگ‌پذیر باشند.
- `pfx_social_rows()` / `pfx_social_icon($row,$size)` — منبع واحد شبکه‌ها برای هدر، فوتر، داک،
  تماس. آیکن سفارشی تصویری با `mask-image` تا رنگ تم بگیرد.
- `pfx_query_items($args)` — یک کوئری مرکزی برای همهٔ ویجت‌های فهرستی (دسته، انتخاب دستی، ترتیب،
  تعداد، آفست، حذف تکراری). کلیدهای سراسری (مثل خاموش بودن یک تاکسونومی) فقط همین‌جا اعمال شوند.
- `pfx_item_cover_id($id)` — تصویر شاخص، وگرنه اولین تصویر گالری. (باگ واقعی: آیتم‌هایی که فقط
  گالری داشتند هیچ‌جا تصویر نداشتند.)

## مدیریت (wp-admin)

**دسته‌بندی‌ها**، **تنظیمات** (تب‌ها: تماس و شبکه‌ها، کاغذدیواری/پس‌زمینه، آیتم‌ها و جلوه‌ها)،

# 02 — ویجت‌های المنتور با تنظیمات بسیار عمیق

## کلاس پایه (همهٔ ویجت‌ها از آن ارث می‌برند)
```php
namespace Brand\Widgets;
use Elementor\Controls_Manager as CM;
abstract class Base extends \Elementor\Widget_Base {
  public function get_categories() { return [ 'brand' ]; }
  public function get_style_depends(): array { return [ 'brand' ]; }
  public function get_script_depends(): array { return [ 'brand' ]; }
  protected function is_dynamic_content(): bool { return true; } // ویجت‌های کوئری‌دار کش نشوند

  protected function sec( $id, $label, $style = false, $cond = null ) { $a = [ 'label' => $label, 'tab' => $style ? CM::TAB_STYLE : CM::TAB_CONTENT ]; if ( $cond ) $a['condition'] = $cond; $this->start_controls_section( $id, $a ); }
  protected function done() { $this->end_controls_section(); }
  protected function txt( $id, $l, $d = '', $x = [] ) { $this->add_control( $id, array_merge( [ 'label' => $l, 'type' => CM::TEXT, 'default' => $d, 'label_block' => true ], $x ) ); }
  protected function sw( $id, $l, $d = 'yes', $x = [] ) { $this->add_control( $id, array_merge( [ 'label' => $l, 'type' => CM::SWITCHER, 'return_value' => 'yes', 'default' => $d ], $x ) ); }
  protected function sel( $id, $l, $opts, $d, $x = [] ) { $this->add_control( $id, array_merge( [ 'label' => $l, 'type' => CM::SELECT, 'options' => $opts, 'default' => $d ], $x ) ); }
  /** اسلایدر که فقط یک متغیر CSS می‌نویسد؛ $resp = ریسپانسیو */
  protected function var_slider( $id, $l, $var, $min, $max, $unit = 'px', $d = null, $resp = true, $x = [] ) { /* selectors: {{WRAPPER}} => "$var: {{SIZE}}{{UNIT}};" */ }
  protected function var_color( $id, $l, $var, $x = [] ) { /* selectors: {{WRAPPER}} => "$var: {{VALUE}};" */ }
  protected function typo( $id, $l, $selector ) { $this->add_group_control( \Elementor\Group_Control_Typography::get_type(), [ 'name' => $id, 'label' => $l, 'selector' => '{{WRAPPER}} ' . $selector ] ); }
  // border(), shadow(), filter(), dims() (padding/margin/radius responsive) به همین شکل
  protected function icon_fields( \Elementor\Repeater $r ) { /* icon(select داخلی) + icon_lib(CM::ICONS) + icon_img(MEDIA) */ }
  protected function row_icon( $row ) { /* اولویت: تصویر آپلودی (mask) → کتابخانهٔ المنتور (Icons_Manager::render_icon) → داخلی */ }
}
```
نتیجه: یک ویجت ۴۰ کنترلی در ۸۰ خط خوانا جا می‌شود و همهٔ ویجت‌ها یکدست‌اند.

## دو نوع کنترل، دو روش اعمال
1. **ظاهر عددی/رنگی → `selectors` روی متغیر CSS.** CSS ویجت فقط `var(--pfx-x, پیش‌فرض)` می‌خواند.
   پیش‌فرض واقعی در CSS است، نه در کنترل. ⇒ ذخیره‌نشدن پیش‌فرض‌ها مشکلی ندارد و تم‌ها هم می‌توانند
   متغیر را بازنویسی کنند.
2. **حالت/چیدمان/روشن‌خاموش → `prefix_class`.** کلاس `pfx-mode-feature` روی wrapper؛ CSS و JS هر
   دو از کلاس می‌خوانند. برای ریسپانسیو: `'prefix_class' => 'pfx-cols%s-'` ⇒ `pfx-cols-tablet-2`.
   ⚠️ `prefix_class` و `selectors` در ویرایشگر بدون رندر مجدد اعمال می‌شوند (سریع)؛ کنترل‌هایی که HTML
   را تغییر می‌دهند `render_type => 'template'` می‌گیرند.

## چیدمان تب‌ها (همه ویجت‌ها یک‌شکل)
**Content:** محتوا → منبع داده → چیدمان → حالت‌ها → جلوه‌ها (هر کدام کلید) → رفتار موبایل.
**Style:** کارت/باکس → تصویر → عنوان → متن → دکمه → آیکن‌ها → حالت hover → جلوه‌ها (رنگ هاله، درخشش...).
**Advanced:** قابلیت‌های سراسری خود افزونه (`03`).

برای هر بخش متنی: تایپوگرافی، رنگ، رنگ hover، فاصله، تراز (ریسپانسیو)، حداکثر عرض، کوتاه‌کردن به N
خط (`-webkit-line-clamp` با متغیر)، پنهان در دستگاه.

## منبع داده (هر ویجت فهرستی)
```
source: all | terms(تاکسونومی A) | terms(تاکسونومی B) | manual(انتخاب آیتم‌ها) | query
query:  orderby (date/title/menu_order/rand), order, count, offset, exclude current, only with image
manual: SELECT2 چندتایی با گزینه‌های get_posts (ترتیب انتخاب حفظ شود)
```
+ **ریپیتر بازنویسی** (`over`): `target` (آیتم یا دسته) + پنهان، عنوان، برچسب بالایی، متن، مشخصات
(خطوط `عنوان | مقدار`)، تصویر، متن دکمه، لینک. کاربر می‌تواند متن هر آیتم را فقط در همین ویجت عوض
کند بی‌آنکه محتوای اصلی تغییر کند. این دقیقاً چیزی بود که خواسته شد.

## حالت‌های چندگانهٔ یک ویجت
یک ویجت با `card_mode` (`prefix_class pfx-mode-`) می‌تواند دو یا چند طراحی کاملاً متفاوت داشته باشد
(مثلاً «حالت ۱: گالری چندتصویری» و «حالت ۲: یک تصویر + توضیح کوتاه + مشخصات + دکمه»). بخش‌های
کنترل هر حالت با `condition` نمایش داده شوند. حالت قدیمی همیشه پیش‌فرض بماند.

برای حالت «تصویر + متن» این کنترل‌ها خواسته شد: سمت تصویر (چپ/راست/بالا/یک‌درمیان)، عرض تصویر،
fit (cover/contain)، فاصلهٔ داخلی تصویر، **شکل قاب در موبایل** (افقی/عمودی/مربع/هم‌شکل تصویر +
نسبت + عرض + ارتفاع)، هاله، برچسب بالایی، متن (کوتاه/بلند/هیچ + تعداد کلمه)، مشخصات (تعداد، سبک،
تعداد در موبایل)، جای دکمه، تراز عمودی/افقی، حداکثر عرض متن، line-clamp، لینک شدن تصویر.

## کارت‌ها و جلوه‌های تعاملی (ماژول مشترک)
`card_fx_controls($prefix)` در Base: کج‌شدن سه‌بعدی (tilt، شدت)، عمق لایه‌ها، درخشش دنبال‌کنندهٔ
نشانگر (glare، رنگ، شدت)، هالهٔ پشت کارت (`halo_switch`)، سایه‌های hover. همه با کلید و
`prefix_class`، و یک handler عمومی JS که `pointermove` را با `requestAnimationFrame` به متغیرهای
`--rx --ry --mx --my` تبدیل می‌کند. روی لمسی غیرفعال یا ملایم.

## رنگ اختصاصی هر آیتم دیتابیسی
- متاباکس «رنگ‌های این آیتم در سایت» با پیش‌نمایش زنده (هاله، درخشش hover، خط، پس‌زمینهٔ آبرنگی).
- `pfx_item_vars($id)` ⇒ `style="--pfx-halo:#..;--pfx-glow:#.."` روی کارت. CSS: `var(--pfx-halo, var(--pfx-halo-global))`.
- تنظیم سراسری (option) برای پیش‌فرض و «خاموش کردن همه»، و کلید `w_halo` در هر ویجت. سه سطح:
  سراسری ← هر آیتم ← هر ویجت.

## آیکن‌ها در ریپیتر
```php
$r->add_control( 'icon',     [ 'type' => CM::SELECT, 'options' => pfx_icon_options(), 'default' => 'link' ] );
$r->add_control( 'icon_lib', [ 'type' => CM::ICONS, 'label' => 'یا از کتابخانه' ] );
$r->add_control( 'icon_img', [ 'type' => CM::MEDIA, 'label' => 'یا تصویر / SVG خودتان' ] );
$r->add_control( 'hide_mobile', [ 'type' => CM::SWITCHER ] ); $r->add_control( 'hide_desk', [ 'type' => CM::SWITCHER ] );
```

## رندر
- `render()` سمت سرور؛ `content_template()` را ننویس مگر لازم باشد (دو منبع حقیقت = باگ). با
  `render_type => 'template'` المنتور ویجت را AJAX رندر می‌کند.
- همهٔ خروجی escape: `esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`.
- تنظیمات لازم JS را در `data-pfx='{"..."}'` (با `wp_json_encode` + `esc_attr`) بگذار، نه در `<script>`.
- لینک‌ها از کنترل URL المنتور: `$this->add_link_attributes( 'btn', $s['link'] )` (target/nofollow/custom attrs).
- `wp_get_attachment_image()` با `sizes` درست و `loading="lazy"` جز تصویر بالای صفحه (`fetchpriority="high"`).
- برای art direction (عکس جدا برای دسکتاپ/تبلت/موبایل) کنترل MEDIA جدا برای هر دستگاه + انتخاب بر اساس **نسبت ابعاد پنجره** نه فقط عرض (نگاه کن 04/08).

## JS ویجت‌ها (یک فایل، یک الگو)
```js
const init = (root) => { if (root._pfx) return; root._pfx = true; /* ... */ };
const scan = (ctx = document) => ctx.querySelectorAll('.pfx-hero').forEach(init);
document.addEventListener('DOMContentLoaded', () => scan());
window.addEventListener('elementor/frontend/init', () => {
  elementorFrontend.hooks.addAction('frontend/element_ready/global', ($el) => scan($el[0]));
});
```
- در ویرایشگر المنتور، DOM ویجت با هر تغییر جایگزین می‌شود ⇒ init باید idempotent باشد و
  منابع قبلی (rAF، observer، WebGL context، React root) پاک شوند. اگر عنصر مانده ولی تنظیمات عوض
  شده، **امضای تنظیمات** را مقایسه کن (`el._sig !== sig` ⇒ پاک‌سازی و اجرای دوباره).
- `elementorFrontend.isEditMode()` برای رفتار متفاوت در ویرایشگر (مثلاً پرده/انیمیشن ورود را رد کن).

## تله‌ها (همه واقعاً پیش آمد)
- شناسهٔ کنترل تکراری با پرو (`sticky`) ⇒ کنترل در پنل ناپدید شد. همیشه پیشوند.
- پیش‌فرض کنترل موجود را عوض کردی ⇒ همهٔ سایت‌های قبلی بی‌صدا عوض شدند. ممنوع.
- `condition` روی کنترلی که مقدارش ذخیره نشده (چون پیش‌فرض بود) درست کار می‌کند — ولی اگر بعداً
  پیش‌فرض را عوض کنی condition هم عوض می‌شود.
- کلاس عمومی `.elementor-element:not(.x)` کانتینرها را هم می‌گیرد؛ انتخابگرها را به
  `[class*="elementor-widget-pfx-"]` محدود کن.
- هاله/درخشش با `position:absolute` داخل wrapperی که `overflow:hidden` دارد بریده می‌شود؛ لایهٔ جدا بساز.

# 03 — قابلیت‌های تب «پیشرفته» برای همهٔ ویجت‌ها و کانتینرها

هدف: هر ویجتی (حتی ویجت‌های خود المنتور و افزونه‌های دیگر) و هر کانتینر، در تب Advanced چند بخش
تازه بگیرد: «شیشه · برند»، «حرکت · برند»، ... . هیچ‌کدام پیش‌فرض روشن نیستند.

## هوک‌ها
```php
// همهٔ ویجت‌ها: بعد از بخش «استایل» تب پیشرفته
add_action( 'elementor/element/common/_section_style/after_section_end', [ __CLASS__, 'widget' ], 20 );
// کانتینرهای flexbox
add_action( 'elementor/element/container/section_layout/after_section_end', [ __CLASS__, 'container' ], 20 );
// (اختیاری، سایت‌های قدیمی) section/column
add_action( 'elementor/element/section/section_advanced/after_section_end', [ __CLASS__, 'container' ], 20 );
```
داخل هر تابع:
```php
$el->start_controls_section( 'pfx_glass', [ 'label' => 'شیشه · برند', 'tab' => CM::TAB_ADVANCED ] );
$el->add_control( 'pfx_glass_on', [ 'type' => CM::SWITCHER, 'return_value' => 'yes', 'default' => '', 'prefix_class' => 'pfx-glass-' ] );
$el->add_responsive_control( 'pfx_glass_blur', [ 'type' => CM::SLIDER, 'selectors' => [ '{{WRAPPER}}' => '--pfx-gb: {{SIZE}}px;' ], 'condition' => [ 'pfx_glass_on' => 'yes' ] ] );
$el->end_controls_section();
```
⚠️ شناسهٔ بخش و کنترل یکتا و پیشونددار (`pfx_`) — این هوک روی همهٔ عناصر اجرا می‌شود و با هر
افزونه‌ای ممکن است برخورد کند. کنترل‌های کانتینر را جدا تعریف کن (برخی بخش‌ها فقط برای کانتینر معنی دارند).

## الگوی اجرا: کلاس + متغیر، یک handler
- روشن‌خاموش و نوع = `prefix_class` ⇒ CSS خالص هرجا ممکن است.
- مقدارها = متغیرهای CSS روی `{{WRAPPER}}`.
- آنچه CSS نمی‌تواند (نشانگر، اسکرول، چسبان در ستون، شمارنده) = یک اسکنر JS که
  `[class*="pfx-mo-"]` و … را پیدا می‌کند، یک `IntersectionObserver` و یک حلقهٔ rAF مشترک.

## فهرست قابلیت‌هایی که ساخته و استفاده شد (برای هر سایت قابل استفاده)
| قابلیت | کنترل‌ها | پیاده‌سازی |
|---|---|---|
| **شیشه (Glassmorphism)** | blur، اشباع، رنگ/شفافیت پس‌زمینه، حاشیهٔ نوری، نویز | `backdrop-filter` + `::before` گرادیان حاشیه |
| **عمق سه‌بعدی** | کج‌شدن با نشانگر، شدت، پرسپکتیو، لایهٔ نور | handler اشاره‌گر ⇒ `--rx/--ry` |
| **ورود با اسکرول (Reveal)** | نوع (fade/up/scale/blur/clip/mask)، تأخیر، مدت، فاصله، یک‌بار/هربار، پلکانی برای فرزندان | IO ⇒ کلاس `is-in`؛ پلکانی با `--i` |
| **هاله و درخشش** | رنگ، اندازه، تاری، شفافیت، تنفس/پالس | لایهٔ `::after` یا span جدا |
| **حرکت حلقه‌ای** | شناور/چرخش/تاب/ضربان، دامنه، مدت، تأخیر | keyframes با متغیرها |
| **دنبال کردن نشانگر** | شدت، معکوس، فقط دسکتاپ | rAF ⇒ translate |
| **پارالاکس اسکرول** | سرعت، محور، محدوده، خاموش در موبایل | rAF + `getBoundingClientRect` |
| **چسبان در بخش (sticky)** | فاصله از بالا (ریسپانسیو)، تا انتهای ستون/والد، خاموش در موبایل | `position:sticky`؛ اگر والد overflow داشت ⇒ fallback با transform (نگاه کن 09) |
| **نمایش متن** | کلمه‌به‌کلمه/حرف‌به‌حرف/خط، ماسک، رنگ گرادیان در حال حرکت | split در JS، `--i` |
| **افکت تصویر** | زوم hover، سیاه‌سفید→رنگی، تاری، کج، ماسک شکل، آبرنگ | CSS filter/transform |
| **نور گذرا (Shine)** | زاویه، رنگ، مدت، در hover یا حلقه‌ای | گرادیان متحرک `::after` |
| **خط پیشرفت اسکرول** | محل، ضخامت، رنگ | متغیر `--p` 0..1 |
| **نوار شناور (کانتینر)** | چسبیدن بالا/پایین، پنهان قبل از اسکرول، جابه‌جایی با هدر | کلاس روی body بر اساس جهت اسکرول |
| **پس‌زمینهٔ اسکچ/کاغذدیواری (کانتینر)** | انتخاب طرح‌ها، تراکم، وزن و اندازهٔ هر طرح، شفافیت، فقط دسکتاپ | SVG/تصویر تکرارشونده با متغیرها |
| **تایم‌لاین اسکرول (کانتینر)** | خط عمودی که با اسکرول پر می‌شود، نقاط مراحل | متغیر پیشرفت |

## قوانین
- هر قابلیت: کلید «در موبایل هم» یا «خاموش در موبایل»، و احترام به `prefers-reduced-motion`.
- هیچ قابلیتی layout را خراب نکند وقتی خاموش است (فقط کلاس + متغیر؛ بدون wrapper اضافه).
- در ویرایشگر هم کار کند (اسکنر روی `element_ready/global`) ولی انیمیشن‌های ورود در ویرایشگر
  فوراً نمایش داده شوند تا کاربر عنصر نامرئی را گم نکند.
- مستند کن: «پیشرفته ← شیشه · برند» دقیقاً کجاست.

# 04 — موشن چندلایه، و تبدیل هر انیمیشن/کامپوننت به ویجت

## مدل لایه‌ای (هیروی «زنده»)
```
لایهٔ ۰  پس‌زمینه    رنگ/گرادیان/letterbox هم‌رنگ عکس (وقتی عکس در قاب جا نمی‌شود)
لایهٔ ۱  تصویر اصلی   <img> واقعی (SEO، فال‌بک) + canvas WebGL روی آن
لایهٔ ۲  ناحیه‌های متحرک داخل عکس: اعوجاج ملایم shader در مستطیل‌های تعریف‌شده (باد در شاخه، تکان گردنبند)
لایهٔ ۳  جرقه‌ها/ذرات (sparks) — DOM یا canvas
لایهٔ ۴  عناصر شناور (floats): تصویرهای PNG (دانهٔ قاصدک، پرنده) با مسیر، دامنه، مدت، عمق پارالاکس
لایهٔ ۵  متن و دکمه‌ها — با «جعبهٔ امن» تا هرگز روی سوژهٔ اصلی عکس نیفتد
لایهٔ ۶  تعامل: نشانگر/ژیروسکوپ ⇒ پارالاکس عمق هر لایه
```
همه در ویجت قابل ویرایش‌اند: ریپیتر ناحیه‌ها (x,y,w,h، نوع حرکت، شدت، سرعت، **برای کدام عکس**)،
ریپیتر جرقه‌ها، ریپیتر شناورها (تصویر، x,y، اندازه، نوع حرکت، دامنه، مدت، تأخیر، عمق، **برای کدام
عکس: همه/عریض/تبلت/موبایل**)، کلید «حرکت در موبایل»، شدت کلی، سرعت کلی.

## عکس جدا برای هر شکل صفحه (art direction)
- سه نسخه: **عریض** (~16:9، دسکتاپ/آیپد افقی)، **تبلت** (~3:4)، **موبایل/بلند** (~5:8).
- انتخاب بر اساس **نسبت ابعاد پنجره**، نه breakpoint عرض: افقی ⇒ عریض؛ عمودی ⇒ نزدیک‌ترین نسبت
  بین تبلت و موبایل (با جریمهٔ کوچک برای تبلت). سرور و JS باید یک الگوریتم داشته باشند (اسکریپت
  inline کوچک در head برای جلوگیری از پرش تصویر).
- برای هر نسخه **جعبهٔ امن** (درصد x,y,w,h ناحیهٔ سوژه) و **ناحیهٔ متن** (چپ/راست/زیر). تابع
  `layout()` فضای آزاد را حساب می‌کند و کلاس می‌دهد: `is-beside` / `is-below` / `is-tight`؛ متغیر
  `--free` برای عرض متن. نتیجه: تیتر در هیچ اندازه‌ای روی گردنبند/سوژه نمی‌افتد.
- عکس هرگز کشیده نشود؛ `cover` با نقطهٔ کانونی = مرکز جعبهٔ امن، و اگر بریدن سوژه لازم شد ⇒ `contain`
  + letterbox هم‌رنگ.
- ⚠️ هر چیزی که برای «عریض» تعریف شد (ناحیه‌ها، شناورها) باید برای نسخه‌های دیگر هم یا تعریف شود
  یا فال‌بک پیش‌فرض داشته باشد. باگ واقعی: قاصدک‌ها فقط روی عکس عریض بودند ⇒ آیپد عمودی و گوشی
  بی‌حرکت. قانون: «در همهٔ حالت‌ها باید حرکت کنند».

## WebGL سبک (بدون کتابخانه)
- یک quad تمام‌صفحه، texture = عکس، fragment shader: برای هر ناحیه (حداکثر ~8 uniform vec4) جابه‌جایی
  UV با `sin(time*speed + uv*freq) * amp * mask(feather)`.
- DPR را محدود کن (`min(devicePixelRatio, 2)`، روی موبایل 1.5)، خارج از دید توقف (IO)، زبانه
  پنهان توقف (`visibilitychange`)، `webglcontextlost` ⇒ برگشت به `<img>`.
- کلاس‌های وضعیت: `is-live` (WebGL فعال)، `is-still` (کاهش حرکت/خطا) ⇒ تست خودکار می‌تواند بسنجد.
- **محافظ اجرای دوباره:** `if (el._mounted && el._sig === sig) return;` و پاک‌سازی stage قبلی.
  باگ واقعی: هیرو ۲–۳ بار mount می‌شد ⇒ ۱۵ شناور و ۲۷ جرقه روی هم و کندی گوشی.

## موشن‌های SVG/CSS (آیکن‌های متحرک داستانی)
- SVG درون‌خطی با `pathLength="1"` و `stroke-dasharray:1; stroke-dashoffset` متحرک = «کشیده شدن خط»،
  ترتیب با `--i`. رنگ‌ها `var(--m-line)`, `var(--m-accent)`, `var(--m-fill)` ⇒ از ویجت قابل تنظیم.
- ویجت «موشن» با انتخاب نوع (کتابخانه‌ای از ۸+ موشن موضوعی)، اندازه، سرعت، رنگ‌ها، کپشن، تراز
  (در موبایل وسط‌چین — خواستهٔ واقعی)، حلقه/یک‌بار با اسکرول.
- عنصرهای جانبی (مثل قلم روی تصویر) کلید جدا داشته باشند — کاربر خواست «قلم را بردار».

## پرده و گذار صفحه (page transition)
- ماژول جدا با صفحهٔ مدیریت «پرده و افکت‌ها»: ۱۰+ سبک (شیشهٔ مات، محو، کشویی، دایره، پرده‌ای، رنگی...)،
  رنگ، تاری، مدت، لوگو/متن روی پرده، فقط اولین بازدید یا هر صفحه، خاموش در موبایل.
- لینک‌های داخلی را intercept کن (نه `target=_blank`، نه `#`، نه با Ctrl/Meta، نه wp-admin/ویرایشگر)،
  پرده را ببند ⇒ navigate؛ در صفحهٔ بعد باز کن. `pageshow` با `persisted` (bfcache) ⇒ پرده را باز کن.

## چسبان (pin) قابل اعتماد
- ستون تصویر چسبان کنار مراحل (مثل «فرآیند طراحی تا مرحله ۵»، «عکس پرتره در درباره»):
  `position:sticky; top:var(--pin-top)`. شرط کار: هیچ والدی `overflow:hidden|auto` نداشته باشد و
  ارتفاع ستون چسبان کمتر از ستون کناری باشد.
- JS تشخیص بده sticky بی‌اثر است (موقعیت در اسکرول ثابت نماند) ⇒ fallback با `transform` محاسبه‌شده
  تا انتهای ستون. `minHeight` ستون رسانه = ارتفاع ستون محتوا.

## GSAP / ScrollTrigger (وقتی لازم است)
- GSAP و همهٔ پلاگین‌هایش رایگان است؛ **محلی** در بسته قرار بده و فقط برای ویجت‌هایی که لازم دارند
  وابستگی کن. `gsap.matchMedia()` برای موبایل/کاهش حرکت. در ویرایشگر روی هر element_ready
  `ScrollTrigger.refresh()` و kill تایم‌لاین‌های قبلی (`gsap.context` + `revert`).

## تبدیل کامپوننت React (21st.dev، shadcn، کدپن) به ویجت المنتور
1. **ریزش کن به داده + رفتار:** هر prop ⇒ یک کنترل المنتور؛ هر آرایه ⇒ ریپیتر؛ هر رنگ ⇒ متغیر CSS.
2. **ترجیح: بازنویسی بدون React** (CSS + JS کوچک) اگر فقط انیمیشن/hover است — سبک‌تر و بدون hydrate.
3. **اگر React لازم است (state پیچیده):** «جزیره»:
   ```php
   // render(): ظرف + props
   echo '<div class="pfx-island" data-c="Marquee" data-props="' . esc_attr( wp_json_encode( $props ) ) . '"></div>';
   // ثبت اسکریپت با وابستگی 'wp-element' (React خود وردپرس ⇒ React جدا نفرست)
   wp_register_script( 'pfx-islands', PFX_URL . 'assets/js/islands.js', [ 'wp-element' ], PFX_VERSION, true );
   ```
   ```js
   const { createRoot, createElement } = wp.element;
   const roots = new WeakMap();
   function mount(el){ if (roots.has(el)) roots.get(el).unmount();
     const r = createRoot(el); r.render(createElement(COMPONENTS[el.dataset.c], JSON.parse(el.dataset.props))); roots.set(el, r); }
   ```
   باندل با Vite/esbuild با `external: react` ⇒ `wp.element`. Tailwind را prefix کن یا CSS را به
   کلاس‌های پیشونددار تبدیل کن تا با قالب تداخل نکند. framer-motion سنگین است؛ معادل CSS یا
   `motion` سبک را ترجیح بده.
4. **ترکیب چند موشن در یک ویجت:** هر لایه یک ماژول با `start/stop/destroy` و یک scheduler مشترک
   (یک rAF، یک IO). ویجت فقط پیکربندی می‌کند.

## کارایی و دسترس‌پذیری (اجباری)
- فقط `transform`/`opacity`/`filter` انیمیت شوند؛ `will-change` موقت.
- خارج از دید ⇒ توقف. موبایل ⇒ تعداد ذره/شناور کمتر (قابل تنظیم).
- `@media (prefers-reduced-motion: reduce)` ⇒ حالت ساکن زیبا (نه صفحهٔ خالی).
- هایلایت آبی لمس را حذف کن: `-webkit-tap-highlight-color: transparent` (خواستهٔ واقعی)، ولی
  `:focus-visible` برای کیبورد بماند.

# 05 — ساخت خودکار سایت، دموهای یک‌کلیکی، تم رنگی، هدر/فوتر

## ایده: «ایمپورت» = ساختن JSON المنتور با کد
به‌جای فایل XML یا Template Kit، صفحه‌ها در PHP به شکل آرایهٔ عناصر المنتور ساخته و در

ترتیب:
1. پیوند یکتا `/%postname%/`، `elementor_experiment-container=active`، غیرفعال کردن color/typography

4. صفحه‌ها (خانه، آرشیو، درباره، تماس، ...) + `show_on_front`/`page_on_front` + منو.
5. «قطعه‌ها»: هدر، فوتر، قالب تک‌آیتم، آرشیو — به‌شکل پست‌های `elementor_library` که parts.php چاپ می‌کند.

- گزینهٔ «ساخت دوباره (force)» فقط با پشتیبان از هر چیدمان.

# 06 — به‌روزرسانی امن: «هیچ تغییری ریست نشود»

> خواستهٔ تکرارشونده و مؤکد صاحب سایت: «من کلی تغییرات روی سایت دادم، نمی‌خواهم هیچ‌کدام با نصب
> نسخهٔ جدید ریست شوند» — «هیچ تنظیماتی که تا الان انجام دادم تغییر نکند، فقط ویژگی‌های جدید اضافه شود».

## چه چیزهایی مال صاحب سایت است (دست نزن)
- `_elementor_data` همهٔ صفحه‌ها و قالب‌ها (هدر، فوتر، هیرو، قاصدک‌هایی که دستی اضافه کرده...)
- کیت المنتور (رنگ/فونت سراسری)، option های افزونه، متای آیتم‌ها، منوها، رسانه.

## روال ارتقا (plugins_loaded)
```php
function pfx_maybe_upgrade() {
  $from = get_option( 'brand_version' );
  if ( $from === PFX_VERSION ) return;
  pfx_ensure_types();          // افزودن term های لازم اگر نبودند (نه تغییر نام موجودها)
  pfx_set_site_icon_if_empty();
  update_option( 'brand_version', PFX_VERSION );
  // هیچ بازنویسی چیدمانی اینجا نیست.
}
```
تابع‌های مهاجرت چیدمان (مثل `pfx_upgrade_120`) اگر لازم شدند: فقط از دکمهٔ صریح «اعمال پیشنهادهای
نسخهٔ X روی سایت من»، با پشتیبان هر صفحه و بازگردانی، و فهرست دقیق تغییرات قبل از اعمال.

## قانون پیش‌فرض‌ها (مهم‌ترین تلهٔ المنتور)
المنتور هنگام ذخیره، تنظیمی را که برابر پیش‌فرض است **ذخیره نمی‌کند**. پس:
- ❌ تغییر `default` یک کنترل موجود ⇒ همهٔ ویجت‌هایی که آن را دست نزده بودند رفتارشان عوض می‌شود.
- ❌ تغییر CSS پیش‌فرض یک کلاس/متغیر موجود ⇒ همان اثر.
- ❌ حذف/تغییر نام شناسهٔ کنترل ⇒ مقدار ذخیره‌شدهٔ کاربر یتیم می‌شود.
- ✅ رفتار تازه = کنترل تازه، با پیش‌فرضی که **دقیقاً رفتار قدیم** را تولید کند (مثلاً
  `f_m_shape` پیش‌فرض `wide` = همان قاب افقی قبلی).
- ✅ اگر شناسه مجبوراً عوض شد (تداخل با پرو): در render بخوان `$s['pr_pin'] ?? $s['sticky'] ?? ''`.
- ✅ ریپیتر: فیلد تازه در ردیف‌های قدیمی وجود ندارد ⇒ `empty($row['for'])` را برابر «همه» بگیر.
- ✅ داده‌های تازهٔ پیش‌فرض (مثل ناحیه‌های متحرک برای عکس موبایل) فقط به‌عنوان **فال‌بک زمان رندر**
  وقتی کاربر چیزی تعریف نکرده؛ نه نوشتن در دیتابیس.

## option ها
- همیشه `wp_parse_args( get_option(...), defaults )` ⇒ کلید تازه خودکار. هرگز `update_option` با
  پیش‌فرض‌ها روی option موجود.
- فهرست‌های تازه (مثل شبکه‌های اجتماعی) تا اولین ذخیره از فیلدهای قدیمی ساخته شوند (فال‌بک) و
  ذخیرهٔ جدید فیلدهای قدیمی را هم همگام کند (سازگاری عقب‌رو).

## CSS و JS
- کلاس‌ها/متغیرهای موجود را تغییر معنا نده؛ کلاس تازه اضافه کن.
- اصلاح باگ ظاهری که «درست»ترش کند مجاز است، ولی در گزارش تحویل صریحاً بگو چه چیزی دیده‌شدنی عوض شد.

# 08 — تست ریسپانسیو، اسکرین‌شات و سنجش حرکت

## محیط تست محلی (بدون سرویس بیرونی)
- وردپرس محلی: `php -S 127.0.0.1:8899 router.php` (+ SQLite یا MySQL محلی)، المنتور نصب، قالب و افزونه
  **symlink** از مخزن ⇒ هر تغییر فوراً روی سایت تست.
- اسکریپت‌های PHP کوچک برای چیدن سناریو (`php run.php ./wp scenario.php`): تغییر تنظیمات یک ویجت در
  `_elementor_data` با `walk_layout`، شبیه‌سازی «سایت صاحب‌کار» (مثلاً ناحیه‌ها فقط برای عکس عریض،
  شناورهای دستی بدون فیلد تازه)، پشتیبان/بازگردانی قبل و بعد.
- Playwright + Chromium برای اسکرین‌شات و سنجش.

## اسکرین‌شات برای کاربر
- کاربر صریحاً خواست: «اندازه‌ها را خودت با اسکرین نشانم بده». برای هر تحویل بصری یک **برگهٔ
  ترکیبی** (grid) با برچسب نام دستگاه و ابعاد زیر هر تصویر بساز (PIL/sharp)، با `deviceScaleFactor: 2`
  برای تصاویری که کاربر می‌بیند.
- اگر کاربر اسکرین مرجع فرستاد («این‌طوری باشد»)، همان اندازه‌ها را کنار هم «مرجع / خروجی» نشان بده.
- برای حرکت: دو فریم یا GIF کوتاه، یا جدول «حرکت می‌کند ✓» برای هر اندازه.

## نکته‌های آیپد و گوشی
- آیپد عمودی نسبت ~3:4 دارد؛ نه «گوشی بزرگ» است نه «دسکتاپ کوچک» ⇒ عکس و چیدمان جدا.
- آیپد افقی 4:3 است (نه 16:9) ⇒ با عکس عریض متن کنار سوژه تنگ می‌شود ⇒ جعبهٔ امن و حالت `is-tight`.
- گوشی‌های بلند (19.5:9) ⇒ عکس «بلند» جدا یا حالت متن زیر سوژه.
- `100vh` در موبایل ⇒ `100svh`/`100dvh`. ارتفاع هیرو در لپ‌تاپ کوتاه (738px) هم چک شود.
- در گزارش صادق باش: «تست در Chromium با شبیه‌سازی دستگاه؛ روی دستگاه واقعی هم ببینید».

## اگر سایت زندهٔ کاربر در دسترس نبود
سناریو را محلی بازسازی کن (تنظیماتی شبیه سایت او) و هر دو حالت «پیش‌فرض» و «شبیه سایت کاربر» را
تست کن. این دقیقاً باگ‌هایی را پیدا کرد که با تنظیمات پیش‌فرض پیدا نمی‌شد.
